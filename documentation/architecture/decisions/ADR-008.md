# ADR-008 — Adoção do Docker para Containerização da Aplicação

- **Status:** Aceita
- **Data:** 02/11/2026

## Contexto

O sistema será composto por diferentes serviços, incluindo backend, frontend e banco de dados, que precisam ser executados e integrados durante o desenvolvimento.

É necessário estabelecer uma estratégia para padronizar o ambiente de execução, facilitar a inicialização dos serviços e reduzir problemas relacionados à configuração e às dependências de cada componente.

Além disso, o projeto tem como objetivo proporcionar experiência prática com tecnologias utilizadas em ambientes profissionais.

## Alternativas Consideradas

- **Docker:** Plataforma de containerização que permite empacotar e executar aplicações em ambientes isolados.
- **Execução local sem containers:** Instalar e configurar diretamente na máquina todas as dependências necessárias para executar cada serviço.

## Decisão

Foi decidido utilizar o **Docker** para containerizar os serviços da aplicação, mantendo cada componente em seu próprio container.

Inicialmente, serão utilizados containers independentes para:

- **Backend:** Aplicação Java com Spring Boot.
- **Frontend:** Aplicação responsável pela interface de usuário.
- **Banco de dados:** PostgreSQL, responsável pela persistência dos dados.

O **Docker Compose** será utilizado para centralizar a configuração e facilitar a inicialização e o gerenciamento dos containers por meio de um único arquivo de configuração.

Para garantir a persistência dos dados do banco de dados, será utilizado um volume Docker associado ao container do PostgreSQL. Dessa forma, os dados serão preservados mesmo quando o container for removido e recriado.

## Consequências

### Positivas

- Padroniza o ambiente de desenvolvimento e execução dos serviços.
- Facilita a inicialização e o gerenciamento dos componentes da aplicação.
- Reduz a necessidade de instalar e configurar diretamente na máquina todas as dependências da aplicação.
- Proporciona experiência prática com Docker e Docker Compose, tecnologias amplamente utilizadas no mercado.

### Negativas

- Introduz uma camada adicional de configuração e gerenciamento da infraestrutura local.
- Exige conhecimentos sobre imagens, containers, redes, volumes e configurações do Docker.
