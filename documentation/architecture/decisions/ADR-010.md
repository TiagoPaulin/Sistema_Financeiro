# ADR-010 — Adoção do Spring Security e JWT

- **Status:** Aceita
- **Data:** 02/11/2026

## Contexto

O sistema disponibilizará uma API REST consumida por um frontend separado, sendo necessário implementar mecanismos de autenticação e autorização para proteger os recursos e controlar o acesso dos usuários.

Também é necessário garantir que as senhas sejam armazenadas de forma segura, evitando a persistência de credenciais em texto puro.

Para atender a essas necessidades, foram avaliadas estratégias de autenticação baseadas em sessão e autenticação utilizando tokens.

## Alternativas Consideradas

- **Autenticação baseada em sessão:** utilizar sessões gerenciadas pelo servidor para manter o estado de autenticação dos usuários.
- **Spring Security + JWT:** utilizar tokens para autenticação das requisições, com gerenciamento de autenticação e autorização pelo Spring Security.

## Decisão

Adotar o **Spring Security** para gerenciamento da segurança da aplicação, utilizando **JWT (JSON Web Token)** como mecanismo de autenticação das requisições à API REST.

A estratégia de autenticação utilizará dois tipos de tokens:

- **Access Token:** token de curta duração, utilizado para autenticar as requisições do cliente à API.
- **Refresh Token:** token de maior duração, utilizado para obter novos Access Tokens sem exigir que o usuário realize novamente o login.

Os Refresh Tokens serão controlados pelo backend, permitindo sua invalidação durante o logout.

Para o armazenamento de senhas, será utilizado o algoritmo **BCrypt**, por meio dos recursos disponibilizados pelo Spring Security.

A autorização será baseada em papéis (*Role-Based Access Control — RBAC*), inicialmente com os seguintes papéis:

- `USER`: usuário comum do sistema.
- `ADMIN`: usuário com permissões administrativas.

## Consequências

### Positivas

- Centraliza o gerenciamento de autenticação e autorização no Spring Security.
- Permite autenticação das requisições sem depender de sessões tradicionais no servidor.
- O uso de Access Token e Refresh Token permite renovar a autenticação sem exigir login frequente.
- BCrypt oferece proteção adequada para o armazenamento de senhas.
- O controle baseado em papéis permite organizar e ampliar as permissões dos usuários conforme as necessidades do sistema.

### Negativas

- Exige implementação e manutenção do fluxo de emissão, validação, renovação e invalidação dos tokens.
- A utilização de JWT exige cuidados com armazenamento, expiração e proteção dos tokens no cliente.
- O controle de Refresh Tokens adiciona complexidade ao gerenciamento da autenticação.
